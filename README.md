# 호텔 동일인 판정 합성 사전 실측

롯데 AX 챌린지 2026 과제 5(롯데호텔 고객 데이터 통합·맞춤 추천) 예선 초안의 동일인 판정을 합성 고객 자료로 미리 잰 기록이다. 표준 라이브러리만 쓴다.

```
python -I -X utf8 run.py smoke            # 돌아가는지만
python -I -X utf8 run.py main out_fix1    # 본 실행(시드 5개, 각 기본 인원 2만)
```

- 규칙·문턱·통과 기준은 `registry.json`에 적고 본 실행 전에 커밋했다(`f4e6a9f`, 2026-11-03 09:58).
- 첫 본 실행 뒤 생성기 버그(무관한 사람끼리 이메일 충돌)를 찾아 고쳤다 → `CHANGES.md`. 첫 결과는 `out/`, 고친 뒤 결과는 `out_fix1/`. 판정 규칙은 건드리지 않았다.

## 결과 (`out_fix1/`, 시드 1~5)

자료: 시드마다 레코드 약 34,400건(사람 약 22,900명), 같은 사람 레코드 쌍 약 13,800쌍. 합치면 안 되는 함정 4종(같은 성 가족 · 배우자 · 쌍둥이 · 동명이인 생일 같음)을 심었다.

| | 자동 합침 회수율 | 잘못 합친 쌍(평균) |
|---|---|---|
| 이 방식 | 69.8% (69.4~70.3) | 5 (2~10) |
| B1 원문 전화 또는 원문 이메일이 같으면 합침 | 50.5% | 1,520 |
| B2 원문 전화와 이메일이 둘 다 같을 때만 | 6.4% | 31 |
| B3 형식을 맞춘 전화 또는 이메일이 같으면 합침 | 87.6% | 2,732 |

- 이 방식의 오병합은 거의 쌍둥이(같은 생일·같은 성·공유 연락처)였다.
- 사람 확인 대기열: 평균 4,535쌍(레코드 1,000건당 132쌍), 그중 82%가 같은 사람. 대기열을 사람이 모두 맞게 처리한다고 치면 회수율 상한 96.2%.
- 묶기: 같은 사람 쌍의 99.4%가 어느 묶음에서든 만났다(평균 87쌍 놓침). 비교한 쌍은 약 10만 7천 쌍으로 전체 쌍의 0.018%, 시드당 1.5초.

**미리 정한 판정: 부분 통과** — B1은 다섯 시드 모두 회수율·오병합 둘 다 이겼다. B3에는 오병합은 크게 적지만 자동 회수율에서 졌다(69.8% 대 87.6%).

## 읽는 법과 한계

- 생성기와 판정기를 같은 사람이 만들었다. 표기 변형·함정 비율은 내가 정한 값이고 실제 데이터의 비율은 모른다. 특히 기준선의 오병합 수는 「가족이 이메일을 같이 쓰는 비율」(등록값 8% × 60%)에 거의 비례한다.
- 자동 회수율이 낮은 이유는 「이름 유사도 0.95 이상일 때만 자동 합침」 문턱이다. 영문 표기가 갈리는 사람(Yi/Lee 등)이 대기열로 갔다. 대기열이 크다(실제 470만 회원 규모로 늘리면 운영 부담이 된다). 문턱을 바꾸려면 새 등록으로 다시 잰다 — 이 결과를 보고 지금 판을 고치지 않는다.
- LLM·메모 읽기·주소 유사도는 재지 않았다. 사람 확인은 시뮬레이션하지 않았다.
