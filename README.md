# hotel-identity-synthetic

여러 시스템에 흩어진 호텔 회원 기록을 「같은 사람끼리」 합치는 판정을, 정답을 아는 합성 고객 자료로 미리 잰 시험이다. 같은 날 세 번 쟀다.

결과부터 적는다. 판정 규칙을 모르는 작성자가 공개 근거로 만든 자료(v2)에서, CI와 연락처로 합치는 상식 기준선은 같은 사람 쌍의 60%를 합쳤지만 다른 사람을 약 1,500쌍 잘못 합쳤다.

미리 등록한 규칙은 잘못 합친 쌍이 거의 0이었는데 자동으로 합친 것도 22%뿐이었다. 결과를 보고 조건 하나를 더한 탐색판(v3)은 자동 55%, 잘못 합친 쌍 8이었다.

미리 정한 통과 기준으로는 세 번 모두 부분 통과다.

## 왜 만들었나

롯데 AX 챌린지 2026 예선에 롯데호텔 과제 「고객 데이터 통합 및 맞춤 추천」으로 낸 기획의 사전 실측이다. 그 기획은 브랜드·지점마다 따로 쌓인 회원 기록을 한 사람으로 묶은 뒤에야 추천을 하자고 주장하고, 그 첫 단계가 동일인 판정이다.

잘못 합치면 남의 투숙·결제 기록이 다른 고객에게 보인다. 못 합친 것보다 훨씬 비싼 실수라고 생각해서, 확신이 낮은 쌍은 자동으로 합치지 않고 사람 확인으로 보내도록 설계했다. 그 비대칭이 숫자로 나오는지, 그리고 그 대가가 얼마인지 보고 싶었다.

## 세 번의 측정

| 판 | 자료 | 판정 | 등록 |
|---|---|---|---|
| v1 | 내가 만든 생성기, CI 없음 | 다중 묶기 + 점수 + 세 구간 | 사전 등록 |
| v2 | 판정 규칙을 보지 않은 별도 작성자가 공개 근거로 만든 생성기, CI 있음 | CI 단계 + v1 규칙 그대로 | 사전 등록 |
| v3 | v2와 같은 생성기, 새 시드 | v2 + 「이름이 거의 같고 연락처 하나가 같으면 합침」 | 결과를 본 뒤 등록(탐색) |

v1을 끝내고 나니 약점이 둘 남았다. 생성기의 비율을 판정기를 쓴 내가 정했다는 것, 그리고 실제 서비스 구조를 빠뜨렸다는 것이다.

롯데호텔 리워즈 가입 약관을 읽어 보니 가입 때 본인인증으로 CI(동일인 식별 연계정보)와 DI를 받고, 이름도 한글과 영문을 둘 다 받는다. 본인인증 회원끼리는 이미 한 사람이다. 판정이 필요한 것은 CI가 없는 기록, 곧 오프라인·트레비클럽 계정이나 비회원 투숙·OTA 예약, 외국인 고객을 그 사람에게 붙이는 일이었다.

v2의 생성기는 다른 에이전트에게 맡겼다. 근거표와 입출력 형식만 주고 판정 코드와 이 문서는 열지 말라고 했는데, 지시로 막은 것이라 증명은 아니다.

근거는 2015 인구주택총조사 성씨 비중, 2007년 여권 영문 성 표기 보도(이→Lee 98.5%, 정→Jung 48.6% 같은 것), 다태아 비율, Pew 2014의 배우자 이메일 공유(18~29세 12%, 65세 이상 47%), 호텔 업체의 프로필 중복 분석이다. 근거가 없는 값은 「가정」이라고 표시했고, 매개변수마다 출처를 [gen_v2/GENERATOR.md](gen_v2/GENERATOR.md)에 적었다.

## v2 결과 — 미리 정한 대로

시드 1~5, 시드마다 기록 약 38,400건(사람 20,000명)이고 그중 52%에 CI가 있다. 같은 사람 기록 쌍은 약 44,700쌍이고, CI 없는 기록이 하나라도 낀 쌍이 약 41,400쌍이다.

| 방식 | 자동 합침 회수율 | CI 없는 기록이 낀 쌍 | 잘못 합친 쌍 |
|---|---|---|---|
| 등록한 판정(CI + v1 규칙) | 22.3% | 16.1% | 0.2 |
| B3 형식 맞춘 전화·이메일 | 57.0% | 55.6% | 4,149 |
| B4 CI 또는 전화·이메일 | 61.4% | 58.3% | 4,363 |
| B5 B4 + 다른 CI는 잇지 않음 | 60.1% | 57.0% | 1,588 |

B5가 잘못 합친 쌍은 대부분 배우자였고, 가족과 대리예약과 남에게 다시 배정된 전화번호가 뒤를 이었다. 이메일이나 전화번호 하나를 같이 쓴다는 이유만으로 한 사람이 된 경우다.

등록한 판정은 잘못 합친 쌍이 거의 없었지만 쓸 수 없는 수준이었다. 사람 확인 대기열이 기록 1,000건당 400쌍이었고, 그중 98%가 같은 사람이었다.

막힌 쌍을 뜯어보니 원인이 하나로 모였다. 시드 1에서 자동으로 합치지 못한 같은 사람 쌍 33,000쌍 가운데 30,000쌍이 생년월일 빈칸이었다. v1 규칙은 자동으로 합치려면 점수 7이 필요해서 이름(+3)과 연락처 하나(+3)로는 6점에 그쳤다.

v1 생성기는 생년월일을 92% 채웠으니 이 문제가 안 보였는데, OTA·SNS·프런트 입력 기록에는 생년월일이 거의 없다. 내 생성기가 내 규칙을 봐주고 있었던 셈이다.

민감도 시나리오 여덟 개(CI 없는 기록 비율, 이메일 공유, 전화 변경, 오타 10%, 외국인 비율)에서도 모양은 같았다. 등록한 판정은 오병합이 한 쌍 이하였고, CI 없는 쌍의 자동 회수율은 11~19%에 머물렀다. CI 없는 기록이 많은 시나리오에서 대기열이 1,000건당 703쌍까지 늘었다.

## v3 결과 — 결과를 본 뒤의 탐색

진단을 보고 조건을 하나 더했다. 이름 유사도가 0.95 이상이고, 형식 맞춘 전화나 이메일 하나가 같고, 생년월일이 충돌하지 않으면 합친다. 이름과 생년월일만 같은 쌍(동명이인·생일 같음)은 여전히 합치지 않는다.

등록부를 먼저 커밋하고 v2에서 쓰지 않은 시드 21~25로만 쟀다.

| 방식 | 자동 합침 회수율 | CI 없는 기록이 낀 쌍 | 잘못 합친 쌍 | 대기열 /1,000건 |
|---|---|---|---|---|
| v3 | 55.5% | 51.9% | 8.4 | 86 |
| v2(같은 시드) | 22.2% | 16.0% | 0.6 | 403 |
| B5 | 60.0% | 56.9% | 1,488 | — |

잘못 합친 쌍은 B5의 0.6% 수준이 됐고, 대기열은 5분의 1로 줄었다. 자동 회수율은 여전히 B5보다 4.5%p 낮아서 판정은 부분 통과다. 결과를 보고 만든 규칙이니 확인이 아니라 탐색으로만 읽어야 한다.

사람이 대기열을 다 맞게 처리한다고 쳐도 회수율 상한은 64%였다. 같은 사람 쌍의 약 9%는 묶기에서 아예 만나지 못했고, 카카오 계정에 이름만 「춘희」로 남은 경우처럼 점수가 사람 확인 문턱에도 못 미친 쌍이 많았다. 이 판의 남은 일은 대기열보다 이쪽이다.

## v1 — 처음 잰 것

v1은 내가 만든 생성기에 CI 없이, 같은 판정 규칙을 쟀다. 형식 맞춘 연락처 기준선의 오병합 평균 2,732쌍이 5쌍으로 줄고 자동 합침은 88%에서 70%로 줄어 부분 통과였다.

첫 실행에서 생성기가 무관한 사람끼리 같은 이메일을 만들어 기준선을 불리하게 만드는 버그를 찾아 고쳤다. 경위는 [CHANGES.md](CHANGES.md)에 적었다. v2를 보면 v1의 숫자는 생년월일이 거의 다 채워진 세상의 숫자였다.

## 이 시험이 말하지 않는 것

v2 생성기도 가정이 많다. 채널 구성, 칸이 채워지는 비율, 기본 오타율, 결혼·자녀 비율은 공개 근거 없이 정했다.

CI 없는 기록 비율을 25~65%로 맞추려고 「오프라인 계정은 온라인 등록 때 CI를 받는다」고 가정했는데, 실제로 그런지는 확인하지 못했다. SNS 간편가입이 CI를 받는지도 모른다.

실제 롯데호텔 데이터는 한 건도 보지 않았다. 여기 숫자는 「이런 구조와 이런 비율이면 이렇게 된다」까지다.

사전 등록은 로컬 git 커밋이다(v1 `f4e6a9f` 09:58, v2 `74a0edc` 10:48, v3 `d8bc056` 10:52, 모두 2026-11-03 KST). 남이 확인할 수 있는 등록은 아니고, 순서를 보여 줄 수 있는 것은 커밋 이력과 이 설명뿐이다. 각 판의 본 실행 전에는 300명짜리 시험으로 돌아가는지만 봤다.

주소 유사도, 사람 확인 처리, 예선 기획의 LLM 메모 읽기와 추천은 이 저장소에 없다.

## 다시 돌리기

파이썬 3.12, 표준 라이브러리만 쓴다. 인터넷 연결은 필요 없다. 윈도우에서만 돌려 봤다.

```bash
python -I -X utf8 run.py main out_fix1      # v1
python -I -X utf8 run_v2.py main out_v2     # v2, base 다섯 시드 + 민감도
python -I -X utf8 run_v3.py out_v3          # v3 탐색
python -I -X utf8 gen_v2/selfcheck.py       # v2 생성기 점검
```

시드가 고정돼 있어서 같은 파이썬이면 결과 폴더와 같은 숫자가 나온다.
